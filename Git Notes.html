02

The mental model

$ git help concepts  ·  read this first

GIT the engine

  • Distributed version control — every clone holds the full history
  • Works offline; commits are local and instant
  • Stores snapshots of your whole project, not diffs
  • Command-line tool, born 2005 (built for the Linux kernel)

GITHUB the hub

  • Cloud hosting for Git repositories + collaboration layer
  • Pull requests, issues, code review, Actions (CI/CD), Pages
  • origin is usually your GitHub repo URL
  • Since 2008 — Git ≠ GitHub, Git works fine without it

Anatomy of a commit

  • A commit is a full snapshot, not a list of diffs
  • Each commit points to its parent(s) — that chain is the history (a DAG)
  • The SHA is computed from content — change anything, get a new ID
  • A merge commit simply has two parents

$git status

The command you'll run 200× a day. What changed, what's staged, what branch you're on. -s → short form

$git add file

Stage one file for the next commit. git add . → all changes in foldergit add -p → pick hunks interactively

$git commit -m "msg"

Snapshot everything staged. Write what & why, not how. -am → skip add for tracked files

$git log

⚡
The golden loop: edit files → git status → git add the pieces you want → git diff --staged to double-check → git commit -m "feat: ...". Repeat. Small, focused commits are future-you's best friend.

Branching & merging

$ man git-branch · git-switch · git-merge · git-rebase
$git branch

List branches; * = current. -v → with last commit · -a → incl. remote

$git branch name

Create a branch (no switching). -d → delete (safe) · -D → force delete-m new → rename

$git switch branch

Move HEAD + update files. The modern way. -c new → create & switch

$git checkout branch

The classic all-in-one (switch / restore). -b new → create & switch

$git merge branch

Pull branch into the current one. --no-ff → always a merge commit--abort → bail out of a conflicted merge

$git rebase maincareful

Replay your commits on top of main → linear history. -i HEAD~3 → interactive (squash/reword)--abort / --continue

⚔

When a conflict hits

CONFLICT (content): Merge conflict in app.js
1Don't panicgit status shows both conflicting files→
2Open & editpick sides between <<<<<<< and >>>>>>>→
3Stage the fixgit add <resolved files>→
4Finishgit commitor git merge --abort to rewind

MERGE preserves history

  • Creates one extra merge commit joining both lines
  • Non-destructive — nothing is rewritten
  • Shows that parallel work happened, honestly
  • Default choice for shared branches

REBASE rewrites history

  • Moves your commits to the tip → perfectly linear log
  • New SHAs are minted for replayed commits
  • Great on private feature branches before a PR
  • Never rebase history others already pulled
branches are cheap. use them.04

Remotes & GitHub

$ man git-remote · git-fetch · git-pull · git-push
$git remote -v

List remotes with URLs. add origin <url> · rename · remove

$git fetch origin

Download new remote commits without touching your files. Look first, merge later. --prune → drop dead tracking branches

$git pull

= fetch + merge. Updates your branch. --rebase → linear instead of merge commit

$git push

Upload your local commits. -u origin branch → set upstream (first push)

$git push origin --delete brcareful

Remove a remote branch. Gone for everyone. --tags → upload all tags too

$git branch -vv

Which local branch tracks which remote — the sync map.

Undo, rescue, survive

$ man git-restore · git-reset · git-revert · git-reflog
safe careful destructive
$git restore --staged filesafe

Unstage a file — your edits stay in the working tree. alias: git reset <file>

$git restore filedestructive

Throw away uncommitted edits in that file. They are gone for good.

$git reset --mode HEAD~1careful

Move branch pointer back 1 commit. --soft → keep staged changes--mixed (default) → keep as unstaged--hard → destroy working tree changes

$git revert a1b2c3dsafe

Undo a published commit by adding an inverse commit. The only polite undo.

$git commit --amendcareful

Fix the last commit: message and/or add forgotten files. --no-edit → keep message

$git refloglifesaver

Every place HEAD has been (~90 days) — even after "lost" work. Find the SHA, then git reset --hard <sha> or re-create the branch.

$git clean -n / -fddestructive

Delete untracked files. -n dry-runs first. Nothing can recover these.

$git cherry-pick shacareful

Copy one specific commit onto your current branch — great for plucking a hotfix.

$git restore --source=sha -- filesafe

Bring back an old version of one file without touching anything else. git show <sha>:<file> → just view it

✚

Emergency room — real situations, real fixes

$ git help "i messed up"
SituationFix
Typo in the last commit messagegit commit --amend -m "fixed message"
Forgot a file in the last commitgit add <file> && git commit --amend --no-edit
Committed on main instead of a branch (not pushed)git switch -c feature/x — commits travel with you. Then reset main: git switch main && git reset --hard origin/main
Need to squash the last 3 commitsgit rebase -i HEAD~3 → mark two as squash, save, reword
Already pushed a bad commitgit revert <sha> then push — never rewrite shared history
Deleted a branch with unmerged workgit reflog → find the tip SHA → git branch <name> <sha>
Broke everything, want yesterday backgit reflog → git reset --hard <sha-of-sanity> (uncommitted work is lost)
Need context-switching right nowgit stash -u → fix the fire → git stash pop
🧭
Breathe. It's almost certainly in the reflog. Once something was committed, it survives ~90 days even when "deleted". The truly unrecoverable zone is only uncommitted + untracked work — that's what git add early and git stash are for.

Stash, tags & .gitignore

$ man git-stash · git-tag · gitignore
$git stash push -m "wip nav"

Shelve uncommitted work; working tree goes clean. -u → include untracked files

$git stash list

The shelf: stash@{0} is newest. git stash show -p stash@{n} → peek

$git stash pop

Apply the newest stash and remove it from the shelf. apply → keep a copy · drop → delete

$git tag

List tags. Freeze a commit forever — releases live here. git tag v1.2.0 → lightweight

$git tag -a v1.2.0 -m "rel"

Annotated tag — a real object with tagger, date, message. Use this for releases. git push origin v1.2.0 / --tags

$git tag -d v1.2.0careful

Delete locally. Remote too: git push origin --delete v1.2.0. git describe → nearest tag + distance

The golden rules

seven commandments of not being the person who broke main

1. Never rewrite shared history

  • No rebase, amend or --force on commits others may have pulled. Public past = read-only.

2. Commit early, commit often

  • Small focused commits are easier to review, revert and rescue than one giant blob.

3. Write messages in the imperative

  • "Add retry logic", not "Added" — they should complete the sentence "if applied, this commit will…"

4. One branch per idea

  • Name them feature/login, fix/header-z-index. Branch off fresh main, delete when merged.

5. Pull before you push

  • git pull --rebase keeps your branch on top and history clean; resolve conflicts before opening the PR.

6. Never commit secrets or junk

  • Maintain .gitignore from day one. If it leaked, rotate it — history remembers everything.

7. When lost, stop pushing buttons

  • git status → git log --oneline --graph → git reflog. Read before you act; almost everything committed is recoverable.
